CleanRL

在教材主线中的位置

深度价值学习策略梯度与 actor–critic最大熵控制

沿章节进入问题设定、推导与实现。实验条件和研究问题在每章末对应列出。

什么时候读：了解 DQN 的 TD target、经验回放和 target network；代码不熟可先完成本站 bandit 实验。

这次只解决一件事：把你已经会的更新式，定位到一个完整训练循环。第一步读懂一个实现，不同时学习 DQN、PPO 和 SAC。

先带着这个例子

DQN 的一次训练先从 replay 取一批历史 transition，构造 target，算损失并更新网络。把 batch size 改为 1，并没有取消 replay，也没有把它变成严格 streaming 学习。

按这个顺序读，不用一遍读完

  1. 先读官方 DQN 文档

    对照算法说明与实现链接，找到环境交互、epsilon 调度、replay 写入和采样的位置。安装以当前官方说明为准。

  2. 在一个训练文件里追踪一次更新

    按 transition → target → loss → backward → optimizer.step 的顺序阅读，再找到 target network 同步、终止处理与日志。

  3. 跑通基础任务后再改协议

    先保存原配置和 commit。再独立增加奖励或动力学变化；记录 reset、优化器和 replay 的生命周期，不能把多项变化混在一起。

读懂核心思路

单文件实现便于看清数据流，但可读性不等于默认支持持续学习。CRL 改造经常隐藏在环境包装、任务切换与统计量重置里，而不只在 loss 中。因此读代码时要同时追踪参数、buffer、环境状态和归一化统计，尤其注意哪些量在 episode 或任务边界被清空。

把理解变成一次检查

环境 reset 以后，网络参数、优化器和 replay 是否都应该清空？

提示

先问 reset 的含义和实验协议，而不是看变量叫不叫 state。

参考思路

没有统一答案。通常 episode reset 只是环境回到起点，并不重置整个学习器；若任务切换额外清空某些状态，那就是协议的一部分，应明确报告并与基线对齐。

读完留下：在代码旁画一张生命周期表：环境／网络／optimizer／replay／target network；记录各自初始化、更新和清空条件。
