从 Search Scaling 到 Learning Scaling

2026年8月24日 · 温颖 · 更新于 2026年8月25日
search-scalinglearning-scalingcontinual-rlllm-agentsharnessbias-variance

Search Scaling 改变的是：一个已经形成的学习者，在当前问题上进行多少计算。Learning Scaling 改变的是：累计经验如何持续改变这个学习者，使其以后在相同计算条件下做得更好，并且仍能继续学习。

The limits of my language mean the limits of my world.
我的语言的界限意味着我的世界的界限。
—— Ludwig Wittgenstein, Tractatus Logico-Philosophicus, §5.6

维特根斯坦讨论的不是机器学习，但这句箴言为 search 提供了一个恰当的入口。对搜索系统而言，它能够使用的“语言”不只是自然语言，还包括道路状态如何表示、哪些驾驶行动可以提出、哪些后果能够预测，以及评价器承认什么是安全且有效。增加搜索计算，可以更充分地探索这套语言已经表达出的候选；它不能自行产生尚未进入表示、行动集合或评价过程的可能性。

自动驾驶系统通常把已经记录的真实道路经验与模拟生成的合成数据用于集中训练。前者保留已经发生的交通交互，后者可以低成本生成稀有路况，改变天气、道路参与者与传感器条件，并提供明确的训练反馈。模型经预训练与 RL 后训练获得道路状态表征、行动后果预测、驾驶策略和近似评价能力，再由 harness 接入车辆控制、安全约束与轨迹选择。

车辆真正驶入施工路段时，可以在当前时刻比较更多制动、等待、转向与绕行轨迹。只要模型和 harness 保持不变，这仍是 Search Scaling：更多计算可以减少良好轨迹已经可达却未被访问的情形，却不能保证模拟器遗漏的摩擦变化、传感器漂移或陌生交通行为突然进入内部表示。实际道路交互仍会产生训练分布与模拟器未曾表达的新条件。

现实中的常见做法，是由工程师分析道路反馈、修订模拟器和训练数据，再集中训练新的共享模型。这条路径能够持续改进车队，却把适应放在两次集中训练之间。运行中的车辆没有因此自动学会：当前行动产生了什么后果、原先哪项预测不再成立，以及这一修正应如何改变以后驾驶。

Learning Scaling 讨论的正是后一项关系。车辆沿第一人称、行动条件的经验流获得真实反馈，持久更新改变以后预测与控制；在相同任务时计算下，长期驾驶表现随累计经历改善，同时维持旧能力保持与后期可塑性。这不意味着安全关键系统应实施无约束在线更新，而是要求把“能否从真实后果持续修正自身”作为独立研究问题。

核心区分：当前 AI 的主导 scaling 路径主要提高了在越来越高层次候选空间中的搜索能力——从输出与推理轨迹，延伸到行动、harness 和 AI 设计。Search Scaling 在既定表示、候选生成、学习目标与评价体系中覆盖更多组合；Learning Scaling 则沿第一人称经验改变以后用于表示、评价、形成中间学习目标和实施更新的学习者。Alberta 式持续强化学习给出了这一区分的强形式：参数、逐参数步长等元参数，以及特征、状态与抽象构造共同持续演进；智能体还要根据自身能力与经历构造以后学什么。若这种演进使智能体在运行后期学得更快，它不再只是适应环境，而是构成运行时 RSI 的候选机制。

Search Scaling：保持初始学习状态、候选生成、评价和停止规则一致，考察当前任务表现或设计提交质量如何随搜索计算变化。

Learning Scaling：先明确长期交互目标、经验产生过程与未来运行条件，再考察连续交互中的长期控制与持续可学习性如何随累计经历变化；诊断同时包括迁移、保持、抽象与中间学习目标的形成及修正、后期可塑性和新任务学习效率。

重置检验可以直接区分两种机制。清空当前驾驶任务形成的任务内上下文、候选轨迹和临时缓存，把下一次行动允许的计算恢复到同一水平，再比较差异是否仍然存在。差异随重置消失，说明优势保存在当前搜索轨迹中；差异在相同计算下继续出现，才可能来自跨任务保留的学习状态。

Search Scaling 与 Learning Scaling 都表示条件响应关系，函数形状可以是幂律、对数关系、S 形或分段函数。前者固定学习状态与搜索程序，研究同一程序如何利用更多计算；后者固定未来任务分布与运行条件，研究经验如何通过学习状态更新影响未来能力。标题中的“到”增加一条研究横轴，不规定技术替代或阶段顺序。

Rich Sutton 在 The Bitter Lesson 中把 search 与 learning 并列为能够利用更多计算的通用方法。二者的实验对象仍须分开：用更多计算寻找更好的当前候选，与从经验中形成可迁移的持久更新，是两种不同的能力形成机制。

预训练与 RL 后训练使大模型获得广泛而不完备的先验：模型可以预测候选行动的后续状态与反馈，可以提出行动，也可以近似评价中间状态与候选轨迹。自回归推断把这些先验展开为搜索；harness 决定哪些状态与行动可达、哪些反馈进入搜索、计算投向哪些分支以及何时提交。推理、智能体规划与工具调用把搜索从回答延伸到行动，AI 研发系统又把 harness、代码、算法与训练流程纳入候选空间。

这一进展仍主要发生在 search 一侧。更多任务时计算能够减少良好候选尚未被访问的有限搜索误差，却不能普遍消除候选本身不可达、状态表示遗漏关键信息或评价过程偏离真实任务效用造成的系统偏差。仅靠离线发布更强模型，也无法及时吸收某个部署智能体沿自身行动形成的路径相关经历。运行时的持续学习所研究的，正是这些经历如何进入持久学习状态，并在以后相同计算条件下改善预测、控制与继续学习的能力。

一、同一表现改善，两种能力形成机制

一条随计算上升的性能曲线，首先要说明计算用在了哪里：是为当前任务展开更多候选，还是通过更新留下了新的持久状态。区分二者还要说明每次独立重复从什么状态开始、在哪个任务分布上评价，以及哪些运行条件保持一致。Scaling 关系需要多个自变量水平和独立重复；曲线可以呈幂律、对数关系、S 形或分段函数，其形式由实验设计与观测数据共同约束。

Search Scaling

先把参数、长期记忆、可复用策略结构与更新规则合称为学习状态；再把状态表示、可行动作、候选展开、评价、计算分配、停止与提交规则合称为搜索程序。对同一任务分布复制多组初始状态相同的系统，保持搜索程序不变，只调整当前任务允许的计算，便可估计任务表现对搜索计算的条件响应。

在自动驾驶系统中，学习状态包含已经形成的道路表征、行动后果预测与控制方式；搜索程序包含传感器观测、可执行行动、轨迹展开、安全评价与提交条件；搜索计算决定当前行动前能够比较多少条轨迹。Search Scaling 只改变最后一项。

一次搜索运行可以形成候选集合、搜索树或行动轨迹，并从中提交一个行动或方案。Search Scaling 研究的是：同一搜索程序如何利用更多计算。若比较中同时替换候选生成分布、评价器、工具接口或工作流，性能差异已经混入搜索程序本身的变化。

搜索计算必须采用明确单位，例如生成 token、候选数、搜索节点、工具调用、环境步数、GPU-seconds 或墙钟时间。不同单位不能在同一横轴中无说明地互换。各组系统从同一个学习状态出发，任务时计算只调节候选展开的方式与规模。

独立重复结束后，若系统恢复到相同学习状态，任务表现随搜索计算的关系就是相应层级上的 Search Scaling。

单次搜索运行内部可以形成搜索树、任务内上下文、中间稿或候选档案。固定学习状态指每次独立重复都从相同初始状态出发，并采用相同的候选生成、评价、停止与提交规则；它不要求运行中的每个搜索节点保持不变。若入选候选被写入下一项独立评估所使用的持久状态，这次提交应作为跨边界更新另行记录。

Learning Scaling

在持续强化学习中，一次经历包括行动前后的观测、行动及其奖励或环境反馈。它不是从外部数据集独立抽取的样本：智能体依据此前的第一人称历史选择行动，行动改变随后出现的观测与反馈，学习又改变以后的策略。累计经历因而沿一条由智能体策略与环境共同诱导的第一人称经验流增长。

存在明确任务边界时，可以在多个累计经历水平清空任务内上下文、暂存推理、搜索树和临时缓存，再在相同未来任务分布与固定运行条件下评价未来任务表现。

持续控制未必具有自然重置点。此时应先声明长期目标，再考察经历增加后的未来交互。奖励率、折扣回报、约束效用或任务特定的长期准则都可以使用；关键是目标先于具体学习算法和实现形式给定，而不是由“系统一直在变”反推出来。

累计经历可以按车辆实际经历的连续观测—行动—反馈步数记录，未来每次行动允许的搜索计算则固定在同一水平。若经历增加后，系统面对道路施工、传感器变化或不同交通行为时仍能更快恢复并改善长期控制，差异就不能再由当次多搜索了多少来解释。

未来能力或持续控制随累计经历形成稳定关系时，经历已经通过持久更新影响以后行为；这种关系构成经历扩展关系。

Learning Scaling 还要同时考察长期任务效用、变化后的恢复、跨条件迁移、旧能力保持、后期可塑性与新任务学习效率。重复题或近邻检索上的提高说明经历能够被再次利用，却不能替代这些响应。

二、历史真实经验、合成数据与部署后的新经验

自动驾驶把现代 AI 的能力形成过程放在同一条时间线上：历史真实经验经记录后进入训练数据，合成数据扩展设计者能够生成和检验的条件，预训练与 RL 后训练把二者转化为共享参数状态，harness 把模型接入具体环境，Search Scaling 在当前任务中展开更多候选，运行时持续学习则利用部署后产生的新经验修正以后决策。

SMARTS 将不同道路参与者之间的交互作为自动驾驶强化学习的核心问题，并以可扩展模拟平台支持多智能体研究。它说明模拟器能够系统组织训练条件，却不意味着模拟器已经完整表达未来道路交互。

这些环节不是互斥路线。历史经验记录与合成数据是集中训练的输入；预训练和 RL 后训练是模型构建期的更新；Search Scaling 是固定学习状态下的任务时计算；Learning Scaling 研究累计第一人称经历与长期控制、保持及可塑性之间的关系。把它们都写成“更多数据”或“更多计算”，会掩盖各自改变的对象。

合成数据的价值取决于生成机制与反馈语义。AlphaZero在规则完备、胜负可判定的棋类中以自博弈产生训练轨迹；Tobin 等人的 domain randomization表明，模拟中的系统变化可以支持特定机器人视觉与控制任务向现实转移。两者都不是“合成数据天然可靠”的证明，而是说明当规则、评价或真实校准提供足够约束时，合成训练可以有效扩展先验。

Sutton 与 Javed讨论的是一个更严格的边界：人类设计的合成数据不能被直接视为超越有限互联网、并替代开放世界持续经验的通用途径。在 Big World 前提下，任何有限模拟器都只能表达真实世界的一小部分；Javed 在同一讨论中也明确承认模拟学习的价值，并提出由智能体从自身经验学习、再以持续学习修正模型。因而争议不在于是否使用合成数据，而在于合成过程能否接受独立于当前近似的现实校正，以及智能体部署后是否仍能从新经验学习。

Silver 与 Sutton 的 Era of Experience把这一区分放在智能体—环境交互中：固定的合成程序会随智能体能力提高而逐渐失去足够难度，能够持续扩展的经验则由智能体行动、环境后果与环境中落地的奖励共同产生。这里的关键不是把“真实”与“合成”作静态分类，而是经验产生过程能否随策略改变、接受外部后果校正，并进入后续学习。

相反，生成程序、奖励与评价器若共享同一遗漏，样本数量增长不会自动补入缺失因素。Shumailov 等人的研究考察了后继生成模型反复从前代生成数据学习的特定过程，并报告尾部信息丢失与 model collapse；这项发现不能推出所有合成训练都会退化，却说明递归生成仍需要来自现实交互、形式规则或外部检验的独立校正。

预训练、RL 后训练与本文所说的 Learning Scaling 都包含 learning，区别不在于“是否更新参数”。区分依据是信号如何产生、更新发生在哪个时间段、形成什么状态，以及研究曲线采用什么横轴。RL 后训练可以使用策略自己产生的轨迹，meta-RL 还可以训练适应程序；只要这些交互发生在具有起止条件的集中训练中，并最终形成面向许多部署实例共享的检查点，它所建立的仍是部署起点。Learning Scaling 研究的是模型投入持续运行以后，某个连续交互学习过程能否把自身行动所诱导的经历继续转化为更好的长期控制和学习能力。

既有知识与继续获得知识不应被写成二选一。预训练与 RL 后训练可以提供强大的初始先验，真正缺少的是部署以后仍能利用自身经历修正这些先验的学习过程。本文采用较宽的学习定义：权重改变既不是必要条件，也不是充分条件。长期记忆、可复用策略结构或 harness 的持久更新也可以承载学习，前提是更新在后续陌生条件中继续影响预测、控制或再学习。

预训练：训练扩展形成部署起点

Kaplan 等人研究语言模型损失与参数、数据及训练计算的关系；Hoffmann 等人进一步分析固定训练计算下参数与 token 的配置。这些工作建立的是训练扩展关系：训练资源与已训练模型之间的响应关系。

预训练本身是一种 learning：数据通过优化形成参数状态。它与运行时持续学习所对应的 Learning Scaling 采用不同的随机过程与评价对象。前者比较训练流程形成的发布状态，后者跟踪连续交互过程如何利用第一人称经历长期发展。

从部署侧看，预训练为候选生成、表征、评价与行动提供先验。预训练形成的候选分布与评价能力会影响任务时搜索曲线，但模型规模曲线与任务时 Search Scaling 曲线仍是两项实验。

RL 后训练：训练期更新，任务期展开

推理强化学习在训练期采样推理轨迹，并用答案、可执行测试或其他反馈更新策略。OpenAI 关于 o1 的技术说明分别讨论 RL 训练计算与测试时思考计算；DeepSeek-R1报告了可验证奖励下较长推理、自检与修正行为的形成。

推理强化学习的运行过程跨越两个时间段。模型构建期从策略中采样轨迹并依据训练反馈更新参数，形成推理、工具使用、回退与停止倾向；当前任务期则在固定的已训练策略下生成更长轨迹、更多分支或更多修订。训练计算增加与任务时计算增加都可能提高表现，但分别属于训练扩展关系与 Search Scaling。

智能体 RL（agentic RL）将训练轨迹扩展到工具调用、环境行动和多步反馈。ReTool训练模型在数学推理中使用代码解释器；Agent Lightning把智能体执行与层级信用分配分离；POAD则把语言智能体的信用分配从完整行动细化到行动内部 token。meta-RL 进一步训练适应程序或学习程序。这些方法改变训练期策略，不能仅因轨迹来自交互就与部署后的持续学习等同。

训练所得策略可以使部署系统更善于搜索、规划与适应。策略投入长期运行后，部署经历能否跨任务保留，并在固定未来运行条件下改善后续能力，仍需由 Learning Scaling 独立考察。

MetaEvolve的公开流程横跨两个时间段。系统先以可执行测试形成的奖励训练多轮反思等元学习能力，再在推断阶段实施 evolutionary search。

前一过程属于 RL 后训练，后一过程属于任务时 Search Scaling。其公开评估覆盖这两个时间段，而非系统运行期间的持续更新曲线。

任务时计算扩展：当前任务中的搜索

Weng 的 Why We Think将任务时计算（test-time compute）组织为并行采样、顺序修订、工具使用、RL 与连续隐空间中的迭代计算。Snell 等人表明，在其数学任务设置中，计算在并行候选与顺序修订之间的分配会随模型和题目难度变化。

持久状态固定时，下列方法都沿 Search Scaling 横轴展开：

  • 并行采样扩展搜索宽度；
  • 顺序修订扩展搜索深度；
  • 工具调用扩大可执行行动集合；
  • 递归委派调整任务分解与并行结构；
  • 智能体规划搜索具有时间结构的行动轨迹。

TTT layers与 TTT-Discover说明当前问题中也可以发生状态或参数更新。若这些更新在问题结束时清空，评价维度仍限于当前问题；若它们跨任务保留，则提供持久学习机制。只有长期控制与持续可学习性随累计经历形成可重复响应时，才进入 Learning Scaling 的经验判断。

Harness 与 AI 设计：Search Scaling 向系统与研发层外扩

Harness 的技术对象是围绕基础模型组织执行、规划、工具、上下文、持久状态与评价的部署系统，而非单一提示模板。Weng 对 harness engineering 的综述采用了这一系统层定义。从 search 的角度看，固定 harness 并增加任务时计算，沿内层 Search Scaling 曲线移动；把 harness、训练程序、代码或架构作为候选，则进入设计层 search。

三、大模型如何实施搜索：训练先验、Harness 与固定搜索的边界

Search Scaling 的自变量是计算，search 的机制则是计算的定向分配。在无法穷举的组合空间中，搜索程序决定如何表示状态、允许哪些操作、从哪里展开、怎样评价中间状态，以及何时停止。候选数只是搜索轨迹的一项统计量。

搜索程序本身参与构造内部空间。状态表示决定哪些差异被保留，可行动作决定哪些路径存在，候选生成 与计算分配决定有限运行中实际访问哪些部分。Guided search 的核心是利用任务结构，使计算集中到更有价值的状态与分支。

经典启发式搜索已经体现了这一点。Hart、Nilsson 与 Raphael提出的 A* 用路径代价与启发函数共同决定节点展开次序；搜索效率来自问题结构，而不是均匀访问更多节点。Wolpert 与 Macready的 No-Free-Lunch 定理进一步说明，在对所有目标函数作均匀平均时，优化算法不存在普遍优势。一个搜索程序在特定任务族上有效，意味着它利用了该任务族的非均匀结构。

现代机器学习把这种 引导信息 部分交给 learning。AlphaZero用学习得到的策略分布引导树的展开，并用价值估计评价叶节点；Snell 等人则表明，大语言模型的并行采样、顺序修订与 可验证评价器 引导搜索，需要按题目难度分配任务时计算。learning 可以形成更好的 搜索策略；在一次任务执行中，固定后的 policy、value 与搜索程序仍然实施 search。

大模型为何能够成为通用搜索器

这里的“通用”不是对所有问题都有效，而是同一个参数化生成器能够依据不同任务描述、上下文和反馈，提出跨领域的候选序列。它首先来自预训练形成的条件 候选生成分布：自回归模型根据输入与已有前缀，为下一步 token、工具调用或行动分配条件概率；完整候选由这一系列逐步选择组成。

大规模异质语料使模型对语言、代码、数学表达、常见任务结构与行动描述形成广泛先验。它至少以三种方式参与搜索。第一，给定当前状态与候选行动，模型可以预测可能出现的后续状态、工具返回或语言反馈，充当近似的环境后果预测器。第二，模型可以直接提出下一步行动或完整轨迹，并按条件概率把计算优先分配给某些分支，充当 候选生成 与策略。第三，模型可以比较中间状态、预测成功概率或判断候选质量，充当近似的价值估计与评价器。同一组参数可以由不同上下文、提示与工具接口激活为这些不同角色。

RL 后训练进一步重塑完整轨迹的分布。终局奖励、过程反馈与工具交互轨迹可以使模型更倾向于分解问题、延长有效推理、调用工具、利用环境返回值或终止无效分支。训练由此共同塑造环境后果预测、行动策略、计算分配倾向与评价能力；推断时增加 token、采样、修订或工具调用，则是在固定先验下展开更多节点。training 形成搜索所依赖的先验，Search Scaling 研究这些先验在运行时如何利用更多计算。

自回归生成还天然给出一棵隐式前缀树：每个前缀是节点，下一个 token、工具调用或环境行动是边。随机采样扩展不同分支，顺序修订沿反馈继续搜索，可验证评价器或环境反馈负责排序与剪枝。Large Language Monkeys在多类任务上报告重复采样随样本数扩大候选覆盖；Snell 等人进一步说明，有效扩展取决于模型能力、题目难度以及计算在并行与顺序搜索之间的分配。TS-LLM用学习得到的价值函数引导大模型树搜索，ToolPRM则在函数调用的结构化输出中以细粒度过程评价引导 beam search。它们共同说明：大模型的搜索能力来自学习得到的候选生成、评价与运行时展开的组合，而不是“生成得更多”本身。

模型仍不等于完整搜索系统。它只对自身可表示的序列给出条件概率，并不知道外部环境中哪些观测应保留、哪些操作真实可执行、怎样获得反馈、何时回滚或提交。把隐式前缀树接入真实任务，需要 harness 把模型输出映射为具有状态、动作和评价语义的搜索过程。

Harness 将任务编译为搜索图

开篇的自动驾驶系统不会枚举全部传感器数值与连续控制序列。状态表示决定道路结构、车辆、行人、施工与传感器条件中的哪些差异被保留；行动接口规定转向、制动、等待与绕行；后果预测决定哪些轨迹值得展开。安全、通行效率与舒适性参与评价，停止和提交规则决定执行哪一步。比较 4 条还是 64 条轨迹，只是这套搜索程序运行了多少计算。

Harness 的作用始于把外部任务编译为内部搜索问题。 外部世界允许的终端行为远多于系统实际能表达和执行的候选。Harness 从任务与学习状态构造有向搜索图。状态表示决定节点包含什么，可行动作与展开算子决定边；评价与计算分配决定哪些节点继续获得计算，停止和提交规则决定最后执行什么。未被传感器或状态表示区分的情形、权限禁止的工具、控制接口无法执行的动作和工作流无法表达的行动序列，都不会进入可达候选集合。

Harness 因而同时执行两种看似相反、实际互补的操作。工具与接口把模型原先无法直接执行的外部行动纳入可达集合；状态表示、类型约束、权限和工作流又排除大量无效或危险分支。前者扩展可执行边，后者缩小需要分配计算的区域，候选生成、评价器与停止条件再在其中实施 引导式搜索。SWE-agent对 agent–computer interface 的研究表明，仅调整文件编辑、仓库导航和测试执行接口，便会显著影响编码智能体的行为与任务表现。Harness 不是附加包装，而是搜索问题的一部分。

可达候选仍不足以描述有限搜索。相同的候选集合可以对应截然不同的状态访问分布，因为 候选生成、评价与计算分配会重新安排节点访问。可达集合描述能够搜索什么，访问分布描述有限计算实际搜索什么；harness 同时决定两者。

从真实任务允许的最佳行为到系统最终提交的行为，中间存在三项相互区分的差距：支持与表示差距说明好行为能否进入内部搜索图；有限搜索差距说明已经可达的好候选是否在有限计算中被访问；评价与选择差距说明好候选出现后能否被正确识别并提交。

三项差距在自动驾驶中有直接对应。支持与表示差距是道路施工方式没有进入状态，或行动接口无法表达某种带有精确时序的协调动作；相应策略从未进入可达候选。有限搜索差距是安全轨迹确实可达、评价也大体可靠，但当次只展开少量分支而没有访问它；这部分可以随计算增加而下降。评价与选择差距是安全轨迹已经出现，系统却因高估短时通行效率或低估稍后风险而提交另一条轨迹；更深入地优化同一评价过程并不保证这部分下降，反而可能更充分地利用 替代目标 偏差。

Harness 会同时改变以上各项。剪枝、类型约束和更集中的候选生成通常减少分支因子与有限搜索波动，却可能扩大支持与表示差距；工具与执行器可以扩展可达集合，却也可能增加分支和随机反馈；更可靠的环境反馈与 evaluator 可以减小模型、评价与选择差距，而固定替代目标的微小系统误差也可能被更深搜索持续利用。因此，harness 体现的是明确的 bias–variance trade-off，而不是“搜索空间越小越好”：它能移动整条条件曲线，但不能仅凭更多约束保证渐近无偏。

Search Scaling 因而表现为一族由 harness 标记的条件曲线。固定 harness 并增加搜索计算，是在同一条曲线上移动；替换 harness，是从一条条件曲线切换到另一条；外层元搜索的对象是能够产生更好条件曲线的 harness。若经历跨任务更新学习状态或 harness，未来曲线也可能随长期运行过程变化。此时必须另以累计经历进行 Learning Scaling 评价。

Harness 改变的是整条条件曲线

固定搜索程序并增加搜索计算，是在同一条 Search Scaling 曲线上移动；替换 harness，则改变可达候选、访问分布与评价过程，得到另一条曲线。曲线的排序可以随任务时计算交叉。只允许短时局部行动的驾驶 harness 可能很快选出可用动作，却因跨越多个路口的协调轨迹不可达而较早进入平台；允许更长轨迹与多车交互预测的 harness 初始较慢，在计算增加后却可能达到更好的驾驶表现。

“更好的 harness”因而必须同时声明任务分布与运行中的计算分配。只在高计算条件下评价，可能选出不适合低延迟部署的设计；只在低计算条件下评价，又可能偏好过强剪枝并低估较宽支持集的后期表现。外层设计搜索使用的计算与候选 harness 在内层任务中接受的计算是两个不同变量。

若高质量候选在 候选生成 中具有非零概率，而且增加计算确实带来足够多样的新候选，那么搜索触及高质量集合的概率会提高。若关键候选不可执行、不能表示或概率为零，覆盖不会因搜索计算增加而出现。即便覆盖已经发生，最终提交仍取决于评价器能否识别相应候选。Large Language Monkeys也报告了这一差别：可自动验证的代码与形式证明中，候选覆盖更容易转化为任务表现；缺少自动 可验证评价器 时，多数投票与 奖励模型 的选择在数百个样本后出现平台。

Gao、Schulman 与 Hilton展示了替代奖励与模拟参照奖励随优化深入而分离的现象；DeepSeek-R1也讨论了 PRM、奖励利用、token 级 MCTS 分支扩张与价值模型的困难。Harness 可以改善候选覆盖与评价，却也可能因过强约束、错误分解或评价失配而较早进入平台。

Harness × Compute 交互实验允许调节任务构成、固定计算与实际计算分布，用于直观看到不同条件曲线的排序变化；其中函数与数值仅作机制示意。

更多搜索计算收敛到什么

任务时计算增加时，Search Scaling 曲线的极限由固定 候选生成、状态表示、可达行动与评价过程共同决定。预训练 scaling 描述训练计算、数据、参数规模与模型损失或下游表现之间的经验关系；它不是关于现实任务求解的一致性定理。训练语料、训练目标和反馈结构与部署任务存在差异时，这些差异会进入候选生成、状态表示与评价器。更多任务时计算只能在固定模型与 harness 给出的搜索图内重新分配访问。若正确行动不在可达候选中，候选生成 对关键分支赋予的概率低到实际计算无法触及，或状态表示丢失了必要差异，搜索只会更充分地求解一个近似的问题。

Kocsis 与 Szepesvári证明的 UCT 一致性提供了有用对照。在有限时域或折扣 MDP、奖励有界、动作集合固定、能够调用目标 MDP 的环境生成模型并持续探索各动作时，采样增加可使根节点选错动作的概率趋近于零。棋类树搜索最容易直观说明这些条件：棋盘状态、合法行动、状态转移和终局胜负来自同一套游戏规则，搜索模拟的对象正是需要优化的对象。这里的关键不是 MCTS 这一名称，而是搜索树、环境转移、奖励与真实优化对象在定理假设中彼此一致。

开放式大模型搜索通常不具备全部条件。候选由训练分布塑造，搜索状态只是现实任务的部分表示，工具反馈可能稀疏或延迟，最终评价也经常来自近似 可验证评价器。增加候选数可以降低固定生成过程下的有限采样误差，却不能自动消除支持与表示差距，也不能使内部评价与真实任务效用一致。搜索会主动寻找评价函数偏好的候选；评价器存在系统误差时，更深入的搜索既可能发现更好的解，也可能更有效地利用 替代目标 偏差。Snell 等人在最困难的题目上报告的任务时计算收益很小，PRM 引导的强搜索在部分低难度题目上还会因利用评价信号而使表现下降。

Harness 在这里承担近似推断中的 bias–variance trade-off。更强的状态约束、类型检查、权限和剪枝减少分支因子，使有限计算集中并降低候选波动；工具、执行器和环境反馈还能补入模型参数中没有的可执行信息。代价是任何固定限制都可能排除正确路径，任何固定 evaluator 都可能保留 替代目标 失配。Harness 可以移动三项差距的大小，但不能仅凭缩小搜索空间保证它们同时趋近于零。

另一项边界来自时间。冻结的 候选生成、评价器和 harness 反映的是构建时的任务分布；部署环境、用户偏好、工具和可行动作持续变化后，原有 引导信息 可能逐渐失配。任务结束即恢复持久状态时，本次搜索发现的错误模式、有效分解和环境规律不会进入后续更新，下一次搜索仍从原有状态展开。Search Scaling 可以反复求解，却不会自动把重复搜索转化为可迁移的更新。

内层引导式搜索与外层设计搜索

固定一个 harness 并增加任务时计算，估计的是同一搜索程序如何利用更多计算。改进 harness 时，外层程序搜索不同设计，并在预先声明的内层运行计算条件下评价每个候选。外层候选数、设计轮数或实验次数属于设计层计算；内层运行条件仍应独立记录。

Automated Design of Agentic Systems让 meta-agent 以代码提出新的智能体工作流；AFlow把代码表示的工作流组织成 MCTS；Meta-Harness让外层程序读取既往候选的代码、执行轨迹与分数并搜索 harness code；AlphaEvolve以程序、父代档案、变异与自动评价实施进化搜索。它们搜索的是产生搜索行为的程序。入选的 harness 被提交后，会限制并引导下一轮任务搜索。

外层能够提出更好的 harness，不保证内层智能体能够利用它。Harness Updating Is Not Harness Benefit据此区分两项能力。一项是产生有用的 harness 更新，另一项是让任务智能体从更新中获益。前者属于设计层 候选生成 的质量，后者取决于对象层策略能否检索、激活并遵循相应 引导信息。两者混在一个端点分数中，便无法判断改进发生在哪一层。

“被搜索对象从回答延伸到 AI 设计”描述 元搜索 的候选单位向外移动；“harness 限制内层搜索空间”描述每个候选程序如何构造任务搜索。两者对应嵌套的搜索问题：

搜索层级被搜索对象主要 引导信息提交位置

代码、数学、内核优化与可执行算法往往先出现清晰的搜索曲线，因为候选可以由测试、编译器、形式约束或明确指标快速评价。开放式研究选题、长期策略与社会环境缺少同等稳定的评价条件；增加候选或扩大 元搜索 并不保证提交质量同步提高。

AI4AI 目前最清晰的自动研发过程，多位于可执行、可比较且反馈周期较短的设计空间。这里扩展的是研发搜索；运行时的持续学习需要采用不同的评价维度。

Darwin Gödel Machine（DGM）提供了一个清楚的两层结构：外层从候选档案选择父代、修改编码智能体程序并评价后继系统；每个候选程序又通过工具、上下文管理与任务分解限制内层编码搜索。主实验中的预训练基础模型保持冻结，因此外层候选增加不等于内层搜索空间变宽；较好的后继程序往往来自更有效的限制与引导。

论文报告，档案中的最佳系统经过 80 轮设计迭代后，在 SWE-bench 上由 20.0% 升至 50.0%，在 Polyglot 上由 14.2% 升至 30.7%。这些端点支持论文设定内的多轮设计改进；横轴是设计迭代与父代选择，并非单一智能体在运行期间累积的经历。建立设计层 Search Scaling 仍需多个迭代或计算水平、独立重复与不确定性区间。

DGM 的候选档案在 80 轮设计运行中持续存在。搜索过程本身也可以保留内部状态：树搜索保存已展开节点，顺序修订保存中间稿，进化搜索保存候选档案。因此，仅检查“状态是否跨迭代存在”还不能确定能力形成机制。

区分这三种结构，需要声明独立重复从哪里开始、哪些随机变量在一次运行内递推、何处施加重置，以及横轴对应哪一类计算或经历：

  • 当前任务搜索以一条问题求解轨迹为一次实现；搜索树、任务内上下文 和缓存可以在轨迹内递推，下一次独立重复恢复到相同初始学习状态；
  • 多轮设计搜索以一条完整的迭代设计轨迹为一次实现；候选档案参与轮间选择，最终提交后继系统；
  • 运行时的持续学习以一条连续的智能体—环境交互轨迹为研究对象；人工任务边界可以清空任务内搜索状态，却不自动重置由先前交互形成的学习状态。

设计层 Search Scaling 的一次独立实现可以包含完整设计轨迹：候选档案在运行内递推，独立重复恢复到相同初始档案与搜索规则。运行时持续学习则让先前经历形成的学习状态继续参与未来行动。前者通过候选、评价与选择产生后继系统，可称为演化式改进；后者发生在连续的智能体—环境交互过程中，可称为发展式改进。这两个名称只描述更新跨越的边界，不能替代 Self-evolving 或 Learning Scaling 的判定。

近期系统也可按这一边界阅读。DeepSeek-R1与 MetaEvolve把训练期参数更新和任务期搜索分开；DGM 让候选档案跨设计迭代；SIA联合更新 harness 与权重；Continual Harness则在不中断环境进程的运行中更新提示、子智能体、工具调用程序与记忆。它们递推的状态与可估计的横轴并不相同。

矩阵定位的是更新过程，而不是为整个系统指定单一类别。同一系统可以同时包含任务搜索、设计搜索与运行时持续更新；相应结论必须落到具体状态转移。DGM 与 Continual Harness 都在轮间递推状态，但前者以设计迭代为横轴，后者才提供连续交互中的在线更新过程。

为什么仅靠离线模型换代不够

离线模型换代擅长吸收跨用户、跨任务的共同结构。一个发布模型完成训练后，到下一次集中训练之前，冻结系统可以扩大任务时搜索，也可以把当前经历放入 任务内上下文 或检索库；若这些状态在任务后清空，部署策略本身仍未随经历更新。只有到下一次集中训练，经过筛选的运行记录才可能进入新的共享参数。

这种离散更新有四项不能由更多当前搜索消除的限制。第一，环境变化发生在两个发布时刻之间，离线更新存在不可避免的适应延迟。第二，个体偏好、组织流程、私有工具和局部失败历史未必能够或适合汇入集中训练。第三，后续观测与反馈的分布依赖智能体当前策略；离线数据记录的是旧策略诱导的经验流，不能完整替代新策略在当前环境中的交互。第四，每次遇到重复结构仍从冻结 候选生成 与评价器开始，会持续支付相似的搜索与验证计算，而不会把已确认的规律写入未来的表示、候选先验或更新规则。

按前述三项差距，Search Scaling 固定 候选生成、状态表示、评价器与学习状态，只增加当前任务计算。运行时的持续学习可以更新其中一部分，例如参数、长期记忆、状态表征、价值估计或 harness。经验驱动的更新可能扩展可达支持、改善计算分配或校正评价，使后续 Search Scaling 曲线发生变化；这只是学习影响未来搜索的中间机制。Learning Scaling 仍以明确长期目标下的持续控制、恢复与持续可学习性为评价对象。

这里的目标不是以无约束在线更新替代离线训练，而是形成两种互补时间常数：集中训练周期性更新群体共享能力，运行时更新吸收路径相关且时效性强的经验。只有长期任务效用、恢复与机会损失随累计经历改善，并且固定未来计算下的迁移、保持、后期可塑性和新任务学习效率没有被牺牲，才支持 Learning Scaling。持久记忆增长、参数更新或搜索曲线移动本身都不充分；更新还可能引入遗忘、评价漂移与新的系统偏差。

Javed 与 Sutton 的 Big World Hypothesis给出了更强的研究判断：对许多决策问题，外部世界会长期比任何有限智能体复杂。智能体只能采用近似，并持续追踪当前经验中与目标相关的结构。这是一项研究假说，不是关于所有环境的定理。

本文的 Search—Learning 区分只需要更弱的条件。固定 候选生成、状态表示或评价过程与部署任务之间仍有偏差；后续交互提供能够修正偏差的反馈；持久更新能够改变未来行动。在这些条件下，更多搜索只能更充分地利用当前近似，learning 才可能改变近似本身。

把上述讨论概括为“合成数据本身无效”会超出其适用条件。合成数据至少有三项明确用途：在规则完备的任务中通过自博弈产生训练轨迹；在可执行验证的任务中生成带有可靠评价的候选；在物理模拟中提高稀有条件的出现频率并改变已知环境参数。它们都可以改善部署前的表征、候选生成、评价和控制先验。这里所强调的限制，是有限生成程序不能穷尽开放世界，也不能替代智能体在部署中继续获得并吸收真实经验。

自动驾驶讨论揭示的限制不是“模拟没有价值”，而是模拟器也必须接受现实交互的持续校正。工程团队根据真实道路中的 sim-to-real 差异修改模拟器，再重新训练共享模型；这是一项由现实反馈驱动的集中学习过程。车辆实际部署后，若摩擦、传感器或交通参与者的行为超出模拟器已经表达的条件，继续从同一模拟器生成数据不会自动补入相应因素。

递归模型生成还有另一类失效。后继模型若持续以先前模型生成的数据替代现实分布，生成误差可能跨代累积并先丢失尾部事件。保留历史真实经验记录、外部检验、自博弈规则或真实环境校准，可以改变这一过程。因此关键差别不是数据由人、模型还是模拟器产生，而是训练信号是否含有独立于当前近似的校正信息，以及校正能否进入以后决策所使用的学习状态。

四、Learning Scaling 的研究对象：连续交互、长期控制与持续可塑性

如果车辆只记住每个路段最终采用的轨迹，它可能在重复路线中越来越准确；更严格的检验会引入道路变化、传感器变化、不同交通行为或控制响应变化，并在学习新规律之后复查此前形成的控制能力。持续强化学习还要考察实际运行过程：变化后需要多久恢复，适应期间增加了多少失败尝试与回报损失，长期控制是否真正改善。Learning Scaling 研究的是：累计经历能否通过学习状态更新改善持续控制，并使智能体在运行后期仍能形成新的预测与行为。

累计经历来自智能体第一人称的行动条件经验流

预训练通常在既定数据集、目标函数和优化程序上进行。持续运行中的智能体却只接收自身传感与交互产生的观测：它不知道一个脱离行动历史的全局环境状态，也不能从所有可能经历中均匀采样。当前行动决定下一次观测的条件分布，学习随后重塑行动分布，未来经历也随之变化。累计经历是这一第一人称、策略诱导过程的时间坐标，不是独立样本的简单计数。

The Alberta Plan把研究单位设为资源受限、持续感知、行动和学习的智能体，并强调时间均匀性（temporal uniformity）；Silver 与 Sutton 的 Era of Experience进一步把经历理解为行动及其环境后果构成的长期流。

Learning Scaling 因而不能简单照搬预训练中的数据量曲线。长期运行应从共同的初始智能体分布与环境过程产生独立轨迹，使每个分支按自身策略形成经历；任务序列重放可以隔离给定经历上的更新差异，却不能替代这种行动—观测耦合。

环境也不会直接交给智能体一份完备而稳定的 Markov 状态。相同当前观测可能来自不同历史，并要求不同的行动；持续智能体必须从第一人称历史递归构造内部状态。这个状态要同时支持对行动后果的预测、长期控制与规划，并随新经历接受修正。仅扩大 任务内上下文 或长期记忆，不能保证历史中的任务相关差异已经进入可用于决策的状态表示。

运行时 learning 因而涉及四项相互依赖的学习机制：从历史构造状态；形成可由后续经验检验的预测与控制知识；把延迟反馈归因于相应决策；调节特征、步长与更新动力学以维持后期可塑性。策略改变经验分布，状态构造改变信用分配所依据的表示。更新动力学又决定智能体以后还能形成哪些特征与行为抽象。这四项共同服务于长期控制，而不是由参数、记忆或 harness 是否变化来定义。

持续强化学习还必须具有从经历中形成抽象的能力。 这里的抽象不是把信息写成更宽泛的语言标签，而是学习哪些历史差异对预测和控制重要、哪些行动序列可以作为时间延展的行为单元，以及应在什么时间跨度上预测行动后果。状态抽象决定预测与决策以什么内部变量为条件；时间抽象使智能体能够在较长时间跨度上组织行为与信用分配。抽象如果完全由设计者预先给定，智能体只能在既有问题表述中更新；当环境出现此前未被表达的结构，它缺少改变问题表述本身的机制。

Sutton 与 Javed把当前系统缺少的能力概括为：从自身经历产生新的抽象，以这些抽象形成预测，并在其上规划；抽象不能由外部一次性指定，因为何种抽象有效取决于智能体实际处于的环境。这里的判断并不是说抽象可以脱离经验产生，而是要求特征构造、状态构造与多时间尺度行为表示在长期交互中持续接受检验和修正。

持续学习还要构造以后学什么

这里需要区分长期控制目标与中间学习目标。前者规定智能体长期应优化的任务效用、胜负准则或安全约束，必须由外部任务定义并接受独立评价；后者规定当前阶段应选择哪类对手、问题、预测误差、行为区分或环境变化来产生下一段有信息量的经历。持续学习不应任意改写长期控制目标，但可以从自身历史与当前能力出发构造、检验和修正中间学习目标。

AlphaZero给出这一分界的清晰例子。棋类规则与终局胜负由外部固定，自博弈并没有自行定义“获胜意味着什么”；它内生地产生对手、局面、行动轨迹和训练分布，使当前策略不断遇到与自身能力相匹配的新问题。与扩大同一局面中的树搜索不同，自博弈改变了以后用于更新策略和价值函数的经验分布。

固定规则下的自博弈只是课程构造的一种形式。Learning to Design Games进一步把环境设计与智能体学习共同纳入优化，使环境产生具有挑战性的训练问题；Diverse Auto-Curriculum说明，持续增加挑战仍不足以覆盖非传递和多样化的多智能体交互；Neural Auto-Curricula则用元梯度共同学习对手选择与响应更新。Language Games把同一问题扩展到角色可变、奖励多样和规则可塑的语言交互，使新的学习问题能够在交互过程中产生。该文属于研究立场分析，尚未给出经普遍验证的持续强化学习算法。

这由此构成 Search Scaling 与 Learning Scaling 的另一项核心差别。固定长期目标、问题表述与学习目标生成机制时，Search Scaling 增加当前问题中被展开、比较和检验的候选；Learning Scaling 则允许经历持久地改变以后选择什么预测、对手、行为区分或环境变化作为学习对象，并检验这种改变是否改善长期控制与迁移。换言之，前者更充分地求解已经形成的问题，后者还要改善形成后续学习问题的过程。

学习目标由系统产生并不意味着它天然正确。固定规则下的胜负可以提供清晰反馈；开放语言与社会交互中的多个奖励、角色和规则则可能冲突、循环或被当前评价器利用。因此，内生学习目标仍须由外部长期目标、约束与独立评估校正，并考察所产生的经历是否提高后续控制、迁移和学习效率。否则，系统可能只是更有效地生成自洽任务，而没有获得面向现实环境的持续学习能力。

Reward Is Enough提出，在足够丰富的环境中，多种智能能力可能作为累积奖励最大化的结果出现。这是一项关于统一目标的研究假说。在本文框架中，长期奖励规定智能体行为最终服务的控制目标；对手选择、辅助预测、探索问题和课程生成属于追求该目标的中间学习结构。Learning Scaling 考察这些结构能否从经验中改进，并不要求智能体任意改写长期目标。AlphaZero展示了 search 与 learning 如何在这一结构中循环：树搜索改善当前行动选择，自博弈产生新的经验，学习再改变下一次搜索所使用的策略与价值估计。

综合 Sutton 与 Silver 的研究线索，本文的区分不是从 search 转向 learning，更不是以持续学习替代规划。The Bitter Lesson 将 search 与 learning 并列为能够继续利用计算的通用方法；The Alberta Plan 把研究对象放在随时间持续更新预测、控制、表征与元参数的智能体上；The Era of Experience 则把长期、行动条件且具有环境后果的交互置于能力形成过程的中心。Learning Scaling 所增加的，是对后两项关系的独立评估：经验是否改变了以后搜索与学习的起点，以及这种改变能否长期改善控制。

持续强化学习还取消了训练期与部署期之间过强的时间不对称。Temporal uniformity 要求感知、行动、预测与学习在长时间运行中由同一类机制反复发生；系统不能依赖一个永远结束于部署之前的特权训练阶段。对非平稳环境，学习目标因此不仅是降低当前预测误差，还包括在分布变化后重新获得良好控制，并控制适应期间的累计机会损失。

累计经历因而首先是给定任务到达过程、环境动力学与反馈渠道下的系统内横轴，不是跨系统通用的资源单位。跨系统比较还需共享可比的机会过程，并同时报告任务构成、反馈密度与可行动作集合；否则两个系统的“一百次经历”可能对应不同的信息条件。

把开篇的直觉改写为同一类自动驾驶系统：它每次始终比较 16 条轨迹，同时利用此前的第一人称经历。只记住某段道路与最终是否顺利通过，可以改善几乎重复的情形；形成可复用的行动后果预测、状态表示与控制行为抽象，则可能在道路、传感器或交通行为变化后继续发挥作用。二者都体现历史依赖，只有后者更可能支持跨条件迁移。

状态更新不能替代持续强化学习的目标

大模型持续学习常把实现机制直接写成研究目标：按时间继续预训练、保留旧基准正确率、扩展长期记忆，或者让参数与 harness 持续变化。这些工作都可能有价值，但它们回答的不是同一个问题。MemRL例如在情景记忆上实施运行时强化学习，展示了非参数记忆更新的一条路线；它直接涉及经历复用与运行时改进，但仍需与参数、元参数和特征构造共同演进的 Alberta 式强形式区分。

Alberta 式 Learning Scaling：改变学习者自身

显式搜索和规划通常在当前任务的结构空间中进行：状态表示、候选生成、价值估计与更新规则在一次独立运行中保持不变，额外计算用于展开更多节点、轨迹或程序组合。候选档案、长期记忆与检索库可以让以后运行访问更多历史内容；若它们只是扩大可检索集合，却不改变智能体如何构造状态、分配信用或从新经历更新，它们仍不等于学习过程自身的演进。

Alberta Plan 提出的研究路线更深一层。时间均匀性要求感知、预测、控制、规划与学习在每个时间步以相同原则持续发生，而不是先完成一个特权训练阶段，再永久冻结学习者。其路线从逐特征、逐参数步长的元学习出发，进入特征生成—检验—替换、历史依赖的状态构造与持续 actor–critic；表示、预测、策略与模型都接受持续更新。这里的关键并非某个算法名称，而是三个学习层次在同一经验历史上联动：

  1. 任务参数改变当前预测、价值与策略；
  2. 元参数调节不同参数的步长、归一化和更新速度，使稳定知识与新结构采用不同时间常数；
  3. 特征、状态与抽象构造持续产生、检验和替换内部表征，并从经验中形成适用于不同时间跨度的状态与行为抽象，改变以后哪些差异能够被预测、评估、规划和控制。

这三个内部层次还要与中间学习目标的构造相连：当前参数、表征与元参数共同决定下一阶段哪些对手、问题和预测差异最值得学习；新经历再检验这些选择，并修正以后目标的生成方式。若这一过程固定不变，智能体可以在给定课程上持续更新，却仍不会改善自己形成后续学习问题的能力。

策略又决定智能体随后接收什么观测与反馈，因此这三层不是对固定数据集的独立优化，而是与第一人称、行动条件经验流共同演进。过去经历由此改变的不只是可调用内容，也包括未来学习将使用的表示和更新过程。这构成本文所说的 Alberta 式 Learning Scaling：随着累计经历增加，智能体自身的学习过程仍能在参数、元参数与特征构造三个层次维持有效更新，并改善长期控制与后续学习效率。

这一定义比“运行时有状态变化”更严格，也比本文对 learning 载体的宽泛定义更强。权重更新并不是所有 Learning Scaling 机制的必要条件；记忆、可复用策略结构或 harness 也可能承载有效学习。但如果目标是让智能体在长期运行中持续形成新的抽象并改善以后学习，单纯扩大存储或保存更多候选通常不够，学习者内部的表示与更新动力学必须能够继续改变。

Abel 等人在行为层把持续强化学习定义为：相对于明确给出的 agent basis，最优智能体必须持续进行行为搜索，而不能最终停留在某个固定基元素。这个定义比“状态一直变化”更严格，也提示一个重要边界：有限实验只能报告已经发生的更新与有限时间内的行为，不能证明智能体以后永不停止学习。

Elelimy 等人进一步指出，传统 RL 中预先给定的 Markov state、episode 边界和有限任务终点，未必适合刻画持续强化学习。对大模型智能体而言，这意味着不能把人工划分的 task sequence 当成唯一研究单位；智能体如何从历史构造状态、行动如何改变以后经验、适应期间的长期回报怎样变化，都属于优化问题的一部分。

一条完整的 Learning Scaling 曲线分为主要目标与诊断量。主要目标描述实际经验流中的长期任务效用、变化后的恢复和适应期间的机会损失；诊断量用于区分迁移、保持、抽象形成与可塑性。至少需要以下六组响应：

  1. 持续控制：明确的长期任务效用是否改善，环境变化后的恢复时间和适应代价是否下降；
  2. 迁移：更新能否提高此前未见且结构存在差异的未来任务；
  3. 保持：吸收新规律后，较早形成的能力是否维持；
  4. 后期可塑性：经历积累很久之后，系统是否仍能学习新的规律；
  5. 新任务学习效率：在匹配的新任务上，达到共同相对性能阈值需要多少新经历；
  6. 抽象形成与修正：新形成的状态或时间抽象能否在结构变化的未来条件中改善预测、规划与控制，并在失效后由后续经历修正；
  7. 学习目标构造与修正：系统后期选择的对手、子问题、预测对象或环境变化，是否产生更有信息量的经历，改善外部评估下的长期控制与迁移，并在不再有用时停止被优先选择。

Learning Scaling 因此是随累计经历变化的一组联合响应，而不是由一个总分表示的单条标量曲线。长期任务效用与恢复描述控制目标；迁移、保持、后期可塑性和新任务学习效率用于判断改善是否来自可持续、可迁移的学习。

未来新任务表现随累计经历的关系只构成经历扩展关系的一部分；实际长期控制、恢复、迁移、旧能力保持、后期可塑性与新任务学习效率都应报告。对任务序列的诊断不能取代智能体在自身行动诱导的经验流中是否实现更好控制。

比较长期运行早期与后期的智能体时，可以记录它们在新任务上达到同一相对性能阈值所需的经历。在任务分布、先验、反馈与运行条件匹配时，后期阶段若系统性地需要更少新经历，才说明学习过程本身有所改善。以下称这种跨阶段关系为递归 Learning Scaling（recursive Learning Scaling）。若系统只是积累了更多知识，未来任务起点可以提高，达到共同相对阈值的适应速度却未必提高。

  • 运行早期：新任务初始表现为 20，达到相对阈值 50 需要 12 条新经历；
  • 运行后期：新任务初始表现为 35，达到更高的相对阈值 57.5 只需 7 条新经历。

后期智能体的阈值更高，却只需要 7 条新经历；在该定义下，新任务学习效率有所提高。若后期起点由 20 提高到 35，但仍需 12 条经历才能弥合一半差距，变化只发生在已有能力，而没有发生在学习效率。

这些数字只解释估计方法；正式实验需覆盖多个新任务、多个阈值与多个长期运行阶段。

可塑性是 Learning Scaling 的必要条件，不是最终目标

在技术上，“模型停止学习”至少包含两种不同失效。灾难性遗忘是吸收新经历后，较早形成的能力受损；可塑性丧失是系统即使继续更新，也越来越难学会后来出现的新规律。前者对应保持，后者对应后期学习能力。只报告旧任务正确率，无法判断系统是否仍能学习；只报告新任务吸收速度，也无法判断较早能力是否被破坏。

Dohare 等人在 Nature 的研究专门把两者分开。其 Continual ImageNet 实验让旧类别继续参与训练，以便把注意力放在可塑性而不是遗忘上。常规反向传播网络在早期连续二分类任务上最高达到约 88% 的测试正确率；到第 2,000 个任务时，多种步长设置的后期表现已接近或低于线性网络。论文还在深度强化学习任务中报告了长期训练后的可塑性退化。作者同时明确说明，前沿大语言模型的系统性长期实验在当时难以承担，因此这些发现不能未经检验直接外推到大模型部署。

Continual Backprop 的作用边界也应准确表述。该算法持续评估隐藏单元的效用，并随机重新初始化一小部分低效用单元，使网络在长期训练中不断获得新的特征候选。Nature 论文在所研究的监督学习与强化学习条件中报告了长期可塑性的维持。它没有表明通用大模型的灾难性遗忘已经解决，也没有建立开放环境中的长期控制或 Learning Scaling。

同一研究路线进一步提出把逐参数步长自适应与“生成—检验”结合。承载稳定知识的参数缓慢改变，需要吸收新结构的部分则保持较快更新；新的内部特征持续产生，再由后续经验检验其效用。这是对下一代持续深度学习的研究判断，不是 Nature 论文已经完成的统一算法。类似地，Oak Lab 的官方使命说明提出单样本更新、无需保存和重放全部历史的实时学习。这种运行方式提高了效率要求，却不是持续强化学习或 Learning Scaling 的定义。

即使保持与可塑性都得到改善，Learning Scaling 仍未自动成立。一个学习器可以保留旧能力，也能吸收新任务，却因为长期目标、状态构造、信用分配或反馈语义不当而没有改善实际控制。本文因而把长期任务效用、变化后的恢复与适应期间的机会损失置于主要位置；保持、后期可塑性、迁移和新任务学习效率用于解释智能体是否仍然可学。

Learning Scaling 因而以连续的智能体—环境交互轨迹为研究对象。比较应覆盖多个累计经历水平，并保持未来运行条件一致，同时估计实际控制、迁移、保持、后期可塑性和新任务学习效率。Continual learning、continual RL、在线适应、长期记忆与 Continual Backprop 可以提供实现机制，却不预先保证这些响应会随经历稳定改善。

五、从状态更新到改进动力学

search 与 learning 说明能力通过什么机制形成。能力形成之后，更新自主程度、优化对象与跨轮改进动力学构成三个相互独立的判别维度：前者描述候选提出、评价、选择与状态写入中由系统执行的环节；第二项描述优化是否指向 AI 系统自身；第三项描述当前能力对下一轮改进速率的因果效应。

Self-evolving、AI4AI 与 RSI 恰好对应这三个维度。它们不是与 search、learning 并列的能力形成机制，也不是一条从低到高的阶段链。

Self-evolving 询问候选提出、评价、选择与状态写入中，哪些算子由系统自主执行；设计搜索、持续学习或二者组合都可能具有这种自主性。AI4AI 询问改进对象是否为模型、算法、训练流程、代码、评价器或研发基础设施，并不规定采用 search 还是 learning。RSI 询问更高的当前能力是否提高下一轮单位时间内的能力变化率；它要求跨轮动力学，而不是一次更新或一个更强后继系统。

Self-evolving 与 AI4AI 可以同时成立而不形成 RSI。自动研发系统可能自主修改 AI 设计，却没有表现出越来越快的能力改进。反过来，人机协作的 AI 研发过程也可能出现正向递归反馈，而不满足高度自主的 Self-evolving 定义。

三个术语之间的独立性可以由三种组合看出：AI 辅助研究者设计训练算法属于 AI4AI，但人类可能保留实验选择权；驾驶智能体可以自主更新记忆与可复用策略结构，但更新对象并非 AI 研发流程；持续学习智能体可以呈现 Learning Scaling，而不改写自身代码或进入自动研发过程。

当前 AI4AI 与 self-evolving 系统中，公开机制最成熟的部分通常是系统组合与设计搜索：语言模型提出代码、harness、算法或训练流程，外部执行器运行候选，自动评价器排序，档案保存被选设计，后继系统再进入下一轮。AlphaEvolve 与 DGM 都清楚体现了这条路线；ML-Master则把并行探索轨迹与选择性记忆用于机器学习工程搜索。它们在可执行、可比较的设计空间中具有真实价值，却主要扩展研发搜索；候选档案增长、系统组件替换或多轮后继系统变强，并不表明一个持续运行的智能体已经学会调节自身参数、元参数与特征构造。

因此，AI4AI 的宽泛标签有时会掩盖两种难度差异很大的机制。一种是把既有模型、工具、评价器和工程组件组织成更有效的外层搜索；另一种是在非平稳、行动条件的经验流中，使学习者自身长期保持可塑性，并让过去的学习改善未来的学习。前者可以为后者设计算法，也可以把 Alberta 式持续学习纳入候选系统；但在相应持续交互评价完成之前，不能把系统工程递推写成底层持续学习已经取得突破。

Alberta 式路径所对应的 agency 不是“能够连续调用工具”这一运行能力，而是一种发展性的自主性：智能体的行动塑造经验，经验更新参数与表征，元学习调节以后更新，新的内部结构又改变随后能学到什么。本文把它视为长期 agency 的一个基础性研究假说，而不是现有系统已经普遍具备的性质。

“递归（recursive）”需要指明循环跨越的边界：

  • Recursive computation：任务内递归调用与子智能体展开，主要增加当前任务搜索；
  • Recursive optimization：多轮设计优化产生后继系统；
  • Recursive learning：在连续交互中，经历既更新当前能力，也改善后续 learning 过程。

RSI 额外要求当前能力的提高抬升后续能力改进速率。递归调用、一次自修改或单个后继系统的性能提高都不足以支持这项推论。

例如，某个后继系统把任务成功率从 30% 提高到 60%，只能说明它在该任务分布上更强。下一轮比较还要保持墙钟时间、人类劳动、计算和评价程序可比。若该系统仍能更有效地提出并筛选 harness 修改，使再下一轮能力提高得更快，AI 研发搜索才开始进入 RSI 所要求的反馈关系。

另一种情形发生在连续交互过程内部：智能体经历许多任务之后，学习陌生规律所需的新交互持续减少，而更高的新任务学习效率进一步加快后续能力增长。运行时的持续学习由此进入 RSI。无论哪条路径，都需要多轮、同一能力指标下的速率比较，而不是两个模型检查点之间的一次分数变化。

两条进入跨轮反馈的路径

RSI 关心的不是相邻两个模型检查点的分数差，而是当前能力是否提高了下一轮的能力改进速率。跨轮比较还应保持能力指标的定义与标定方式不变。

在人类劳动、训练与推断计算、数据访问、实验设施及评价程序可比时，较高的当前能力若使后续能力改进速率系统性提高，才形成 RSI 正向反馈。

当前能力与下一轮改进速率同时上升，仍不足以说明前者促成后者。更强的检验应采用配对分支：一条分支使用本轮改进后的组件，另一条冻结或替换为上一轮组件，并保持外部投入与评价口径可比；两条分支在下一轮改进速率上的差异才对应改进组件的反事实作用。

第一条路径是 AI 研发搜索：当前能力通过更有效的候选生成、评价、实验与提交，提高下一轮研发的能力变化率。

AI 研发搜索路径通常属于 AI4AI，并不要求单一智能体在部署中持续学习。AI 研究工具、自动实验平台与人机研发组织都可能形成同类反馈。Aschenbrenner讨论的 AI 研发自动化情景主要位于这条路径。

第二条路径是 运行时的持续学习：当前能力改善状态构造、信用分配与可塑性调节，使后期新任务学习更快，并进一步提高后续能力变化率。

智能体不仅形成知识与策略，还改善状态构造、信用分配、表征学习、行为抽象发现、步长调节或更新门控，使后期新任务需要更少经历。递归 Learning Scaling 是这条路径的重要中间条件。

学习效率的提高进一步增加后续能力改进速率时，运行时的持续学习才构成 RSI 所要求的正向反馈。

Cunningham 等人的经济模型把反馈写成局部生产网络中的弹性，并区分正向反馈与自我维持的加速。在其最简 stock–flow 条件中，总反馈弹性大于一才足以使能力增长率随能力水平上升。这个阈值依赖模型假设；局部正向反馈不能直接外推为长期加速。

六、如何评估 Search Scaling 与 Learning Scaling

任何 scaling 分析都应给出自变量、保持不变的系统构成、评价任务以及多个自变量水平。只比较“低计算”与“高计算”，或比较训练前后的两个端点，只能说明局部差异；它们不能单独确定响应函数的形状，更不能证明幂律关系。

Search Scaling 的评估

Search Scaling 的评估从同一初始学习状态出发，保持模型、harness、任务分布、候选生成、评价与停止规则一致，仅改变当前任务可使用的计算。横轴可以采用候选数、搜索节点、工具调用、环境模拟步数、GPU 时间或墙钟时间，但同一条曲线必须采用一致定义。

主要响应可以是任务回报、成功率、约束违反率或提交质量。仅报告端点表现仍不足以解释机制，还应区分三项限制：高质量候选能否进入可达集合，有限计算是否实际访问了它，以及评价过程能否正确选择它。候选覆盖、有效多样性、评价校准和选择错误由此成为诊断量；它们用于解释曲线为何上升、进入平台或随搜索加深而下降。

前述形式定义还要求区分系统性差距与跨运行波动。在能够获得外部任务价值参照时，可对同一任务、同一学习状态和同一 harness 重复运行，在每个计算水平分别估计 b(c;x)b(c;x)b(c;x) 与 σ2(c;x)\sigma^2(c;x)σ2(c;x)；跨任务汇总则另行反映任务构成的差异。若现实最优价值不可得，就不能直接宣称搜索已经无偏，而应以可达候选覆盖、环境后果预测误差、evaluator 校准和选择错误说明尚能观测的部分。

Learning Scaling 的评估

Learning Scaling 先给出持续交互中的长期控制目标，再在多个累计经历水平比较以后表现。未来每次决策可使用的搜索计算、工具权限和评价程序应保持一致，从而使差异来自经历经持久更新对以后行为的影响，而不是以后任务获得了更多计算。

形式上，每个累计经历水平 eee 对应一个由实际交互产生的学习状态 Λe\Lambda_eΛe​，评价读取的是共同未来计算 c∗c^*c∗ 下的 FL(e∣c∗)F_{\mathrm L}(e\mid c^*)FL​(e∣c∗)。经历增加但未来计算也同步增加时，只能观察联合变化，不能把全部差异归因于 Learning Scaling。

持续运行与新任务诊断承担不同作用。持续运行保留策略与经验之间的依赖，用长期回报、奖励率、约束违反、环境变化后的恢复和相对于时变可行参照的动态遗憾评价控制。新任务诊断则在清空任务内上下文、搜索树和临时缓存后，考察迁移、旧能力保持、后期可塑性与达到共同性能水平所需的新经历。前者回答长期控制是否改善，后者解释改善能否延伸到以后学习；任何单项都不足以替代另一项。

固定记录经历的重放可以比较不同更新规则在给定经历下产生的差异，但它切断了行动对以后观测的影响。因此，重放适合分析更新规则，不构成持续强化学习的完整评价。持续交互中的独立重复必须允许不同策略形成不同的第一人称、行动条件经验流，再比较其长期控制与继续学习能力。

二维响应：经历如何改变搜索

Search Scaling 与 Learning Scaling 可以置于同一二维坐标：横轴改变任务时搜索计算，纵轴改变持久更新已经吸收的累计经历。每个经历水平都估计一条完整的 Search Scaling 曲线，便可判断学习是否改善候选生成、评价与计算分配，是否推迟平台，或是否因错误记忆和评价失配使更多搜索反而有害。反向作用同样重要：搜索选择哪些行动，也决定智能体以后能够学习的经验。

四种组合比较冻结或更新学习状态，以及固定或增加任务时计算。它们把联合改善分为任务时搜索的变化、给定经历下持久更新的变化，以及学习状态是否改变了搜索对计算的响应。只比较“冻结且低计算”与“更新且高计算”两个端点，三项作用仍会混在同一个分数差中。

评价至少应报告持续交互中的长期任务效用、变化后的恢复时间、未来新任务表现、达到共同性能水平所需经历、旧能力保持、后期可塑性，以及系统构造的中间学习目标是否带来可迁移的控制改善。总体平均分可能掩盖适应期间的机会损失、可迁移任务分布收缩、旧能力损失或后期学习停滞。

对 Alberta 式 Learning Scaling，还应报告学习发生在哪一层。只增加可检索历史的系统，可与固定特征、仅更新任务参数的系统比较；逐参数步长等元参数更新，应与相同步长或仅采用常规优化器的系统比较；特征生成—检验—替换与状态构造，则应与固定特征空间的系统比较。所有比较保持未来任务时计算一致，并观察持续控制、新任务学习效率与后期可塑性，而不是仅记录参数变化量或存储条目数。只有三层联动确实改善以后学习时，才支持“学习者自身随经历演进”的结论。

还需要区分局部对照与完整响应关系。高、低两档计算或经历只能估计局部变化；建立响应曲线需要多个水平、重复运行、不确定性区间，以及未参与拟合的外推区间。Weng 的 Scaling Laws, Carefully所强调的拟合敏感性同样适用于这两条曲线。

二维响应同时呈现 search 与 learning 的交互：

  • 持久更新可能改善候选生成、评价器与计算分配，使 Search Scaling 曲线整体上移或平台延后；
  • 搜索可能主动选择信息量更高的经历，提高持久更新的效率；
  • 错误记忆、候选多样性下降或评价器失配，也可能使二者产生负向交互。

search 与 learning 不构成排他选择。稀有、组合性强且难以复用的问题适合保留任务时搜索；反复出现并具有迁移结构的规律适合进入持久更新。科学问题在于识别二者各自适用的任务分布，并用两条独立横轴估计主效应与交互效应。

Search、Learning 与跨轮改进的关系

Search 与 Learning 不构成价值排序。 Sutton将 search 与 learning 并列为能够随计算扩展的通用方法；AlphaZero更直接展示了二者的互补：学习形成策略与价值估计，搜索利用它们分配节点展开。这里增加 Learning Scaling 横轴，是为了区分“当前求得更好”与“未来学得更好”。联合评估还会检验学习能否改善候选生成、评价与计算分配，从而改变 Search Scaling 曲线。

未来任务起点与新任务学习效率是不同的量。 Chollet强调新任务学习效率：更强先验可以抬高任务起点，却未必减少达到同一相对性能阈值所需的新经历。因此，Learning Scaling 需要同时报告未来任务起点、完整适应曲线和达到共同阈值所需的经历。任务内重置只服务于迁移与可塑性诊断；Alberta Plan与 Era of Experience关心的实际持续交互则由配对长期运行保留，不能由重置实验替代。

AI 研发搜索与运行时持续学习构成两条不同的反馈路径。 AlphaEvolve、DGM 和自动实验平台可以通过更有效的 候选生成、评价、实验与提交产生更强后继系统；这条路径不要求单一部署智能体持续学习。运行时持续学习路径则研究智能体能否在交互中改善状态构造、信用分配与可塑性，使后期面对陌生任务所需的新经历减少。两者都可能进入 RSI，但都需要在外部投入可比时检验当前能力是否提高下一轮改进速率。

这一区分也保留了工程与经济上的开放性。关于基础设施投入回报、AI 应用价值与持续学习需求的讨论说明，持续更新即使技术上成立，也要与冻结模型、任务内上下文、检索、引导式搜索和周期性离线训练比较总成本、延迟与可靠性；反之，某条路线较易部署，也不能替代机制归因。

由此得到四项可检验的经验预期。前两项对应近期技术发展，第三项规定 RSI 的经验条件，第四项给出条件性的工程选择：

  1. 近期静态基准与可执行任务预计仍将主要由训练扩展关系、RL 后训练和 Search Scaling 推动；
  2. AI4AI 中的设计搜索预计会早于广泛的递归 Learning Scaling 建立稳定曲线；
  3. Self-evolving 系统可以长期自主运行而不形成 RSI；RSI 必须由跨轮改进速率及相应因果对照支持；
  4. 若部署期持续更新无法在固定未来运行条件下维持迁移、保持与后期可塑性，冻结模型配合搜索、检索和周期性离线训练仍可能更合适。

结语

历史真实经验记录使模型接触已经发生的世界交互，合成数据扩展设计者能够生成和检验的条件，预训练与 RL 后训练再把二者转化为表征、候选行动、后果预测和近似评价能力。它们共同形成强大的部署起点，也使大模型成为通用搜索器；但外部训练数据再多，仍不同于部署智能体沿自身行动获得的新经验。训练分布、生成程序、奖励与真实任务之间的残余失配，会继续进入后续搜索。

固定模型的任务时计算扩展因而主要降低有限搜索差距；它不会自动消除支持与表示差距，也不会自动校正评价器与真实任务效用之间的系统偏差。MCTS 的渐近一致性只能在搜索模型、环境转移、奖励与真实优化对象满足特定假设时成立，不能直接外推到开放式大模型搜索。

换回开篇的自动驾驶：安全轨迹已经可达、却因当次展开不足而没有出现，可以通过更多搜索补足；道路变化没有进入状态表示，协调动作无法提出，或评价过程持续高估短时通行效率而低估稍后风险，则不会因候选数量继续增加而自动消失。Search Scaling 是否逼近真实任务最优解，取决于前一类有限搜索误差之外的条件是否同时成立。

Harness 通过表示、限制、工具和 引导信息 组织搜索：它可以扩展可执行支持、减少无效分支并改善选择，也可能排除正确路径或保留 替代目标 失配。设计层程序则搜索 harness、代码、算法和训练流程。在当前来源快照中，最清晰的能力扩展仍沿任务搜索与 AI 研发搜索展开，但增加搜索计算与利用长期经验改善控制仍是两类不同过程。learning 可以改变后续搜索曲线，这只是二者交互的一种表现。

Search Scaling 研究同一持久状态上的任务时计算；Learning Scaling 研究行动条件经历能否改善持续控制并维持持续可学习性；RSI 研究当前能力对后续改进速率的反馈。三者可以相互作用，却描述不同的经验关系。

长期能力增长很可能同时依赖两者：搜索产生可供比较的轨迹与经历，学习把其中可复用的结构保留到未来；持久更新又可能改善后续的候选生成、评价与计算分配。AI4AI 可以设计更好的搜索过程和学习过程，RSI 是否成立则仍取决于跨轮能力改进速率。

标题中的“到”为能力增长增加一条独立的研究横轴。任务时搜索和 AI 研发搜索已经提供越来越多可估计的计算响应；尚待建立的曲线是：在长期目标与经验产生过程明确、未来运行条件固定时，行动条件经历能否持续改善同一智能体的长期控制、恢复、迁移、保持、后期可塑性与新任务学习效率。

即使系统允许持续更新，深度学习过程也可能在长期运行中逐渐失去形成新特征与新行为的能力。更多经历由此不必然带来 Learning Scaling，正如更多任务时计算不必然消除固定搜索的表示与评价偏差。前者要求学习过程长期保持可塑，并服务于实际控制；后者要求搜索先验与真实任务之间的偏差同时得到校正。

任何被称为“自我改进”的系统都应报告四组信息：搜索程序对候选的表示、限制、展开与评价方式；持续交互所优化的长期目标；跨越任务或设计迭代边界的学习状态；当前能力对下一轮改进速率的影响。四组信息依次确定 Search Scaling、持续强化学习、Learning Scaling 与 RSI 所需的经验判断。

术语定义

术语本文含义
学习（learning）经历引起持久状态更新，并由该更新影响以后条件中的预测、行动或继续学习
训练（training）依据数据、目标函数、优化程序与停止条件实施状态更新；预训练、监督微调和 RL 后训练均属于训练
测试（testing）在预先给定的任务集合、评价指标与运行条件下估计性能
部署（deployment）系统面向实际用户、任务或环境运行的时期；部署可以只有推断，也可以包含持久更新
推断（inference）已有状态与当前输入经过计算产生预测、回答或行动
推理（reasoning）为形成判断或行动而实施的中间计算
搜索（search）在给定候选空间中生成、展开、评价并选择候选
规划（planning）比较具有时间次序的行动及其后续影响，并选择行动序列或策略；规划可以由搜索实现，搜索不必涉及规划
智能体（agent）在持续交互中接收观测并选择行动，且行动影响后续观测与反馈的系统
运行时的持续学习智能体在部署交互中保留由经历引起的更新，使其继续影响以后预测、控制或学习
持续强化学习智能体沿第一人称、行动条件经验流持续学习，并面向明确的长期控制目标
Harness围绕基础模型组织任务内上下文、工具、智能体协作、工作流、权限、记忆、评价与提交条件的系统构成

全文中的 Search Scaling 与 Learning Scaling 均指在明确横轴与保持条件下估计的响应关系。任务时训练若只服务当前任务并在重置后清空，属于任务内适应；更新跨任务保留并影响以后条件时，才进入运行时学习。
